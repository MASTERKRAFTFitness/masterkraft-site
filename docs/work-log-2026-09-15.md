## The afternoon: freight numbers that were not true

### 6. The Easyship record corrected itself twice (`c45f3ca`)

Two measurements from the 11th that had never been written down, both correcting
something the file already asserted.

**"693ms and 1136ms" was a cache hit.** The two calls were identical bodies, so
the second came from Easyship's own result cache — which is exactly what made
them useless as a timing. Properly phase-timed against varied destinations:

| | n | min | median | max |
|---|---:|---:|---:|---:|
| Novel quote | 12 | 2.82s | **5.52s** | 7.67s |
| Repeated body | 5 | 1.14s | 1.43s | 2.20s |
| DNS + TCP + TLS | 6 | 0.06s | 0.17s | 0.54s |

It is not our connection, and our own cache absorbs the repeats — so the number a
customer waits for is always the slow one.

**TNT is single-parcel only.** Not merely the only carrier quoting bulky: a
second carton of any size drops it and leaves UPS Express, the dearest service in
the pool, as the customer's only option. A real cart came to **$450.00** as one
consignment against **$249.07** split — 1.81x. `partitionConsignments()` was
already shipped; this is the record of why.

### 7. A 116cm barbell was being quoted as an 11.6cm parcel (`4708481`)

The item the previous session left open, and it did **not** need the WooCommerce
write it was thought to need.

The density guard added last week catches a slip of ten in *every* axis at once,
because a barbell in a matchbox is denser than any metal. It cannot catch a slip
in **one** axis. `MWBBFUR03` is a 16kg fixed barbell recorded in the frozen
snapshot as 11.6 x 18.3 x 18.3cm — every side in bounds, 4,100 kg/m³, denser than
water and nowhere near steel. An entirely ordinary box. The bar is 116cm.
`MWBBFUR05` is the same fault at 11.7 against 117.

**Not a price difference — a different kind of shipment.** 11.6cm sits inside
every Australia Post parcel limit; 116cm is past the 105cm one, so the real
carton is oversize freight on its own consignment with Australia Post refused.

The snapshot cannot be corrected: WooCommerce has been frozen since the cutover
and its writer was deleted that morning (`d1604ea`). So the tie is broken on
**provenance** — where the ERP holds a plausible carton that CONTRADICTS the
snapshot's, the ERP wins. `cartonsContradict()` is the predicate: half again on
any axis, sides sorted first because the two systems order their axes
differently.

**The blast radius was measured before the rule was written.** Of the 631 codes
holding a complete carton in both systems:

| | |
|---|---:|
| agree inside 5% | 562 |
| disagree ~10x — already rejected as implausible | 67 |
| disagree 5.8-6.3x while the snapshot stays believable | **2** |
| anything between 1.05x and 5.76x | **none** |

Nothing in the middle, so the threshold has an empty margin either side. Replayed
over the whole catalogue: 756 resolvable lines, **exactly 2 change**, and both
move from *parcel* to *oversize*. Weights need no such rule — of 632 codes
holding one in both, not one differs by so much as half again.

### 8. The agent had a second carton resolver (`0e363cb`)

Found while checking what else reads a carton. `quote_freight` promises "the same
prices the website checkout would show" and then read `product.dimensions`
straight off the snapshot — no plausibility guard, no ERP, no axis remap. So
every carton the checkout skips or overrules, it answered from anyway: all 42

**Not an internal tool.** `public-tools.ts` reuses the implementation, so the

itself came back "not in the catalogue". Both faults now go through
`refsToFreightItems()`.

## The evening: subgroups got URLs (`eeb31b0`)

The site had 11 category pages and nothing between them and 500 products. A
`ProductSubGroup` — "Plyometric Boxes", "Squat & Power Racks", "Kettlebells" —
was expressible only as `?sub=` on the category page, and that page
canonicalises every facet away on purpose. The term a buyer searches for had no
URL to answer with.

The old store's nested `/equipment/<category>/<sub>` is the shape Google still
ranks on this domain — §5's gymnastics find is the proof, and the morning's
redirect had sent that ranking signal to a facet that canonicalises straight back
to the broad category.

**29 pages, from data that already existed.** No ERP entry, no photography. In
the sitemap at their parent's weight, and linked from the category's own facet
bar.

**The list is hand-written, and that is the point.** `npm run report:subgroups`
— added here — counts **57 subgroups, 31 with three cards or more**, counting
CARDS rather than product codes, because a range's nineteen sizes are one card
and thinness is what makes a doorway page. Generating a page per subgroup is how
a catalogue grows fifty pages listing what their category page already lists. A
subgroup gets a URL when somebody has written a reason for it to exist, and
`subcategories.test.ts` holds that copy to the rule `lib/product-copy` is held
to: no weight, dimension, gauge or warranty term the system cannot check, a
60-word floor, meta between 70 and 165 characters, and a trigram-overlap ceiling
so thirty pages cannot be one template.

**Six subgroup names sit under two categories** — "Squat & Power Racks" is 20
cards under Rigs & Racks and **one** under Strength, which is exactly the punch
list's *FILED UNDER THE WRONG GROUP* row. Every stray falls under the three-card
floor, so no competing page exists today, and the test refuses a second page for
any name so fixing those rows in Unleashed cannot create one.

### The redirect had to move into `proxy.ts`

Written first as `permanentRedirect()` in the page, it served a **meta refresh
under a 200** — the `[category]` segment has a `loading.tsx`, so the body is
already streaming by the time the page runs. The same trap
`[category]/layout.tsx` documents for `notFound()`, and Next's own loading docs
name `proxy` as the fix. Verified against a running server:

| URL | |
|---|---|
| `/equipment/body-weight/gymnastics` | **200** |
| `/equipment/body-weight/not-a-real-sub` | **308** → `?sub=` |
| `/equipment/packages/dumbbells` | **308** → `?sub=` |
| `/equipment/nonsense/foo` | **404**, untouched |
| `/admin` | **307** → login, untouched |

The `next.config.ts` catch-all is gone: redirects match before routing and it
shadowed the route completely.

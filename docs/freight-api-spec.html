Freight API

What we need from a freight provider's API to quote, book and track bulky consignments from our website checkout, and to write the result back into Unleashed, our ERP. This document is the technical scope only.

Scope

What we are integrating

Four calls. Quote at checkout, book on payment, receive status, and write the consignment number back to our ERP.

#CallWhenDirection
1rateCustomer reaches checkoutWe call you, synchronously
2bookPayment succeedsWe call you
3statusConsignment movesYou call us, webhook
4ERP writeAfter bookingEither side, see section 4

Everything is server to server. Our checkout prices delivery on the server and never accepts a freight price from the browser.

Constraint · read this first

Rate stability

We call rate twice for every order

Once when the customer reaches checkout, to display options. Again on the server at the moment we charge the card, to compute what to actually charge. Between those two calls the browser holds only service.id, never a price.

The same inputs must therefore return the same price for at least 30 minutes, and service.id must be stable across both calls. If your pricing is not deterministic, return a quote token with a stated lifetime that we can redeem on the second call instead.

When the second call disagrees with the first we fail the order rather than charge a different number, so a drifting rate is a lost sale, not a rounding difference.

Call 1 of 4

Rating

Synchronous, on the checkout path, with a customer waiting.

Request

POST /rate
{
  "collection": { "postcode": "3074", "suburb": "Thomastown",
                  "state": "VIC", "country": "AU" },
  "delivery":   { "postcode": "2150", "suburb": "Parramatta",
                  "state": "NSW", "country": "AU",
                  "residential": true },
  "items": [
    { "sku": "MCTMSP02", "quantity": 1, "weight_kg": 601,
      "length_cm": 185, "width_cm": 91, "height_cm": 56 }
  ]
}
FieldTypeNotes
collectionobjectConstant. Always Thomastown VIC 3074.
delivery.residentialbooleanKnown at checkout. Drives tailgate and any residential surcharge.
items[].skustringOur product code, echoed for reconciliation against your invoice.
items[].quantityintegerEach unit is a separate carton. We do not consolidate.
items[].weight_kgnumberGross, carton included.
items[].length_cmintegerRounded up. Same for width_cm and height_cm.

That is the complete set of what we hold per line. We do not have pallet counts, stackability or dangerous goods classification. If your API requires any of those, tell us and we will discuss whether we can derive them.

Response

{
  "quote_id": "q_01J8XZ...",          // optional, see Rate stability
  "expires_at": "2026-08-25T04:30:00Z",
  "services": [
    {
      "id": "road-standard",
      "name": "Road Freight",
      "service_level": "standard",
      "price": 284.50,
      "price_includes_gst": false,
      "eta_days_min": 3,
      "eta_days_max": 6,
      "chargeable_weight_kg": 612,
      "surcharges": [
        { "code": "tailgate", "description": "Tailgate delivery", "price": 45.00 }
      ]
    }
  ]
}
FieldHow we use it
services[].idRequiredStored on the order, sent back at payment and at booking. Must be stable.
services[].nameRequiredDisplayed to the customer verbatim.
service_levelRequiredOne of standard, express, courier. We show the cheapest service plus the fastest that beats it, so we need a comparable level.
priceRequiredNumeric, AUD.
price_includes_gstRequiredExplicit boolean rather than an assumption. Getting this backwards misprices every order by 10%.
surcharges[]RequiredCoded and priced separately, not folded into price. We itemise delivery for the customer.
eta_days_min / maxRequiredRanking and display. Without these we cannot identify the faster service.
chargeable_weight_kgOptionalTells us when a consignment cubes out rather than weighs out.
quote_id / expires_atConditionalRequired only if pricing is not deterministic. See Rate stability.

When you cannot quote

Return a coded reason, not an empty services array. We show the customer a different message for each, and an empty list is indistinguishable from a fault. 

{ "services": [],
  "error": { "code": "outside_network",
             "message": "No service to postcode 2150" } }

Please supply the full set of codes you can emit. At minimum we need to distinguish outside your network, item too large or heavy to carry, and temporary failure, retry.

Performance

  • p95 under 2 seconds. A customer is waiting on this response.
  • All line items in one request. Per carton calls are workable but multiply the latency.
  • Tell us your rate limits. We call this once per checkout view.

Call 2 of 4

Booking

Called once payment succeeds. No human rekeying.

Request

POST /book
{
  "service_id": "road-standard",
  "quote_id": "q_01J8XZ...",          // if quotes are tokenised
  "order_number": "490118",
  "delivery": { "name": "...", "phone": "...", "email": "...",
                "address_1": "...", "suburb": "...", "state": "...",
                "postcode": "...", "residential": true,
                "instructions": "..." },
  "items": [ /* same shape as the rate call */ ]
}

Response

FieldNotes
consignment_numberRequiredAvailable in this response, not only in a portal or a confirmation email. Written to our ERP.
order_numberRequiredEchoed back. This is the key that ties your record to ours.
label_urlRequiredOr base64 PDF. Printed at despatch.
tracking_urlRequiredShown to the customer and emailed.
number_of_packagesRequiredPiece count. Written to our ERP.
chargeable_weight_kgPreferredSo our records match what you invoice.
pickup_datePreferredExpected collection.

Preferred  An endpoint to cancel or amend a consignment before pickup, since orders are occasionally changed after payment.

Call 3 of 4

Status callbacks

A webhook per status change. Polling is an acceptable fallback but we would rather not run a scheduler for it. 

POST <our endpoint>
{
  "consignment_number": "...",
  "order_number": "490118",
  "status": "in_transit",
  "status_description": "Departed Melbourne depot",
  "occurred_at": "2026-08-25T04:30:00Z"
}
  • Signed, so we can verify the callback came from you. HMAC over the body is fine.
  • The full list of status codes you can emit, not a sample. We map them onto a fixed field in our ERP, so we need the complete set up front.
  • Proof of delivery retrievable against the consignment number, if you capture it.
  • Retry on non 2xx, so a brief outage on our side does not lose an event.

Call 4 of 4

Writing back to Unleashed

Unleashed is our ERP and the system of record for dispatch. Every website order already exists there as a sales order under the same order_number we send you.

Unleashed exposes a SalesShipments object. These are the fields that need to be populated against that order number:

Unleashed fieldSource
OrderNumberOur order number, unchanged
ShippingCompanyYour company name
TrackingNumberconsignment_number from the booking response
DispatchDateFrom the despatch status event
NumberOfPackagesnumber_of_packages
ShipmentWeightchargeable_weight_kg
ShipmentStatusMapped from your status codes

Either party can do this write. If you already integrate with Unleashed, say so and we will use it. Otherwise the booking response and status webhook above give us everything we need to write it ourselves, and we are happy to build that side.

Environments

Authentication and sandbox

  • Server to server credentials: API key or OAuth client credentials. No browser calls, so no CORS requirement.
  • Separate sandbox and production credentials.
  • The sandbox must be able to return failure cases, not only successes. We build and test the "cannot quote" path deliberately, and we cannot do that against an endpoint that always succeeds.
  • Sandbox bookings must not create real consignments or generate charges.
  • A documented approach to versioning, so a change on your side does not break checkout without notice.

Constraints

Values your API must accept

These are the extremes in our catalogue. They are stated here as input validation limits, not as typical consignments.

InputMust accept up to
Single line item weight601 kg
Single carton longest side268 cm
Single carton volume1.12 m³
Distinct line items per request8
Total cartons per consignment30

An API that rejects a 601kg line item, or silently truncates a dimension, fails at checkout rather than at integration time. Please confirm these are within range.
